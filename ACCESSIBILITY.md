# Accessibility

Accessibility matters because School Algerian Manager should be usable by as many people as possible, including people who use different devices, input methods, browsers, or assistive technologies.

This document describes our accessibility goals, expectations for contributors, known limitations, and how to report accessibility barriers.

## Priorities

School Algerian Manager aims to provide an accessible and understandable experience across its user interface.

Our accessibility priorities include:

* Clear and readable content
* Logical page structure and navigation
* Keyboard-friendly interaction where practical
* Sufficient visual clarity and readable text
* Meaningful labels for forms and interactive controls
* Useful error and status messages
* Responsive layouts for different screen sizes
* Avoiding unnecessary reliance on color alone to communicate information
* Supporting users with different levels of technical experience

Accessibility is an ongoing goal. The project does not currently claim verified conformance with a particular accessibility standard.

## Contributor expectations

Contributors should consider accessibility when making changes to user-facing features.

When contributing:

* Use clear and descriptive text for buttons, links, forms, and navigation.
* Keep interactive elements understandable and usable.
* Avoid introducing unnecessary keyboard barriers.
* Use appropriate labels for form fields.
* Make error messages clear and actionable.
* Avoid using color as the only way to communicate important information.
* Keep layouts usable on smaller screens.
* Consider users who may rely on keyboard navigation or assistive technologies.
* Test user-facing changes locally before submitting a pull request.

For accessibility-related changes, contributors are encouraged to describe what was changed and how they tested the affected feature.

## Reporting accessibility issues

If you encounter an accessibility barrier while using School Algerian Manager, please report it so that it can be investigated and improved.

You can report an accessibility issue by opening a GitHub Issue in the repository or by contacting:

**[elhadriallal@gmail.com](mailto:elhadriallal@gmail.com)**

When possible, please include:

* The page or feature where the problem occurred
* What you were trying to do
* What happened
* What you expected to happen
* Browser and browser version
* Operating system
* Device type
* Assistive technology or input method, if relevant
* A screenshot or screen recording, if helpful

You do **not** need to disclose any disability or medical information when reporting an accessibility issue.

### Severity

Accessibility issues may be considered based on how significantly they prevent someone from completing a task.

Examples:

* **High:** A user cannot access or complete an important feature.
* **Medium:** A significant barrier makes a feature difficult to use, but an alternative method is available.
* **Low:** A minor usability or accessibility issue that does not prevent the task from being completed.

Maintainers may assign or adjust the severity during issue review.

## How we respond

Accessibility reports will be reviewed as part of the project's normal issue-management process.

When possible, maintainers will:

1. Review the reported barrier.
2. Try to reproduce the problem.
3. Determine its impact.
4. Identify a possible fix or workaround.
5. Update the relevant issue with progress.
6. Verify the change when a fix is implemented.

Response and resolution times may vary depending on the complexity of the issue and available project resources.

If a workaround is available, it may be provided while a permanent improvement is being considered.

## Ownership and maintenance

Accessibility is maintained as part of the project's general development and maintenance process.

The project maintainer is responsible for:

* Reviewing reported accessibility barriers
* Considering accessibility during user-interface changes
* Reviewing accessibility-related contributions
* Updating this document when the project's accessibility practices change

This document should be reviewed when significant changes are made to the application's interface or development process.

## Supported environments

School Algerian Manager is intended to work in modern web browsers on common desktop and mobile devices.

The project may be used with:

* Keyboard and mouse input
* Touch input on supported devices
* Modern desktop browsers
* Modern mobile browsers

Accessibility support may vary depending on the browser, operating system, device, and assistive technology being used.

The project does not currently claim that every browser, device, or assistive technology combination has been fully evaluated.

## Known limitations

Accessibility testing is an ongoing process, and some areas of the application may still contain barriers.

Potential limitations may include:

* Some interface elements may not yet provide complete support for screen-reader users.
* Some pages may require additional keyboard-accessibility improvements.
* Some visual components may need further accessibility testing.
* Accessibility behavior may vary between browsers and assistive technologies.
* Not every application workflow has been evaluated with assistive technologies.

Users are encouraged to report specific barriers so they can be investigated and tracked.
